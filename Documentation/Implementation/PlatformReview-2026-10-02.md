# Platform/disclosure review — 2 October 2026

This review prepares RR-11-05. It does not publish the app, configure Google Play, enable real billing, or certify the current development APK for production. Actual store linking is deferred by the user; the local shop must remain labeled as simulated and must never charge money. Final artifact inspection and remaining owner configuration are tracked separately.

| Area | Current official requirement and project action |
|---|---|
| Target API | New Android phone apps and updates require API 36 from 31 August 2026. Inspect the generated APK; the authoring configuration uses the highest installed SDK. Do not infer the artifact target from `Auto`. [Google Play target API policy](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en) |
| Native page size | Google's current compatibility page requires 16 KB support for 64-bit apps targeting API 35+, and now states that incompatible app updates cannot be released from 1 February 2027. Verify ZIP alignment and every native ELF library; a POCO X2 run alone does not test a 16 KB runtime. [Android page-size guidance](https://developer.android.com/guide/practices/page-sizes) |
| Random draws | Odds must be disclosed before and near purchases of randomized virtual items. Native Talent/KK review shows the 75% Common / 22% Rare / 3% Legendary distribution and card-level behavior; inspect these on the phone. Actual localized store price and checkout integration remain deferred. [Google Play payments policy](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en) |
| Privacy/Data safety | Disclosures must reflect actual off-device processing by both the game and bundled SDKs. Removing ads does not automatically establish that all data collection is absent. Preserve current Analytics/Crashlytics switches and verify the artifact/configuration. The privacy draft still needs owner identity, support, retention and deletion details before publication. [Google Play Data safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en) |
| Signing/distribution | Current acceptance uses a debug-signed, separate playtest package. Final local replacement must match the installed game's package/signature and preserve data. A later Play release needs the owner's production package, upload key, console configuration, access/testing declarations and actual store evidence. These must not be invented or inferred from a sideload. |

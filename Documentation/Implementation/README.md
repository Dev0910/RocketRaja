## Reproduction

Run from the repository root with .NET 10, Node 24.14.0 and Unity 6000.4.9f1. Server deployment targets Node 22; tested language/API features are supported there. Server dependencies use their committed lockfile: `npm ci --ignore-scripts` in `Backend/Premium`. No Unity package upgrade is needed.

1. `dotnet run --project Tools/RedesignLab -- --parity-export`
2. `node Tools/RedesignLab/CheckModelParity.cjs`
3. `node Tools/RedesignLab/RunReferenceModel.cjs` (full 125-scenario model rerun), then `node Tools/RedesignLab/CheckReferenceReport.cjs`
4. `npm --prefix Backend/Premium test`
5. `Tools/CloudSaveTests/run.ps1` uses the verified portable Java 21 pointer under ignored `Library/RedesignTestRuntime/`; [version, source and checksum](JavaTestRuntime.json). An explicit `-JavaHome` remains supported. The runner refuses a live project/nonlocal emulator.
6. Unity menus: **Rocket Raja / Redesign / Validate Core And Save Codec**, **Validate Content And Isolation**, **Validate Content Regeneration**, and **Profile Core In Editor**. Exact editor entry points are `RedesignCoreValidation.Run`, `RedesignAuthoring.Validate`, `RedesignGenerationValidation.Run`, `RedesignPerformanceValidation.Run`. The ordinary `ValidateGame.Run` entry point also selects the redesigned core; legacy validation is available explicitly through `ValidateGame.RunLegacy`.
7. `Tools/RedesignDeviceQA/build.ps1` creates a fresh isolated diagnostic project and prints its build paths. Follow [its protocol](../../Tools/RedesignDeviceQA/README.md); phone installation was authorized and succeeded on 2 October. Android may still present its local install prompt.
8. `node Tools/RedesignLab/PublishEvidence.cjs` publishes the input/output hash inventory; `node Tools/RedesignLab/PublishEvidence.cjs --verify` verifies that snapshot. Refresh this inventory when new accepted evidence changes a report.

Existing-screen ad removal and its disposable Play Mode regression setup are reproducible through [AdRetirement/README.md](AdRetirement/README.md). The old 308-check report remains historical; the current legacy compatibility run has 310 checks after retirement. Evidence images are hashed as exact binary bytes; text uses BOM removal and LF normalization.

Release isolation checks: `Rocket Raja / Redesign / Validate Release Isolation` and `node Tools/RedesignLab/CheckReleaseSymbols.cjs`. The compiler matrix uses actual core sources with simulated Unity symbols; it does not create a Unity/IL2CPP release artifact or establish release acceptance.

The distribution check uses 250,000 draws with seed **739103** and a six-sigma binomial tolerance per card. Live selection uses secure randomness; test seeds never configure live selection. Model cohorts use seed **1009 × history number** (1–32 free, first 16 paired per pack and no-Legendary). Policy overrides, exact active management/reveal time, actual visit gaps, events and daily results are saved in each scenario JSON and its manifest. Quantiles use observed nearest ranks.

Parity shares a canonical saved threshold as boundary input and compares independent threshold construction numerically. Only the policy's automatic post-prestige draws are suppressed for the immediate-reset comparison. No economy coefficients or original model formulas changed; the published simulation report therefore needs no tuning revision. A one-ULP C# reward-boundary bug was fixed and is covered by exact/adjacent representable cases.

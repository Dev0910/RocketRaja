`Bootstrap.unity` selects the session and enters the saved `ClassicProductionCanvas` in `Main.unity`. `ClassicApplication` binds that session to the existing economy and persistence owners. The current Main contains the camera, event system, active Classic canvas and preserved inactive `ClassicProductionCanvas__LegacyDisabled_20261019`. Classic authoring targets Main directly. Shared product artwork, shop decorations and fonts retain their existing asset paths. See [cleanup and reference verification](Implementation/ClassicCleanup/README.md), [production integration](Implementation/Classic-Production-Integration.md), and [save/account acceptance](Implementation/Classic-Save-Account-Integration.md).

The approved shopkeeper tutorial is integrated into this saved canvas (30 October). Fresh states explicitly enroll in optional `ShopkeeperTutorialState` version 1; missing/version-zero data preserves existing-player behavior. `RedesignTutorial` stages receipts with the ordinary save-before-publish commands and captures actual purchase/claim/draw results. `ClassicTutorial` observes ready gameplay, presents each automatic route once, updates the authored CTA pointer, and suspends during recovery, modals, offline receipts and committed reveals. The scene contains every dialogue, hand, help button and TMP material slot before Play Mode. [Contract, interaction matrix and verification](Implementation/Tutorial-Native.md).

## Historical redesign implementation — 2 October 2026

This section records the earlier presentation, superseded by Classic. Its preview scene and screen prefab are retired; the economy and shared presentation helpers remain in use.

The new economy uses `RedesignCatalog`, `RedesignState`, `RedesignEngine` and `RedesignSaveStore`. The authored 1,000-entry/28-card asset and manifest are versioned and validated against their source. Commands persist staged state before publishing it. Exact natural-number counters hold Fame, card levels, credits and KK. `RedesignRuntimeDriver` binds the lifecycle: offline settlement precedes input, menus keep production running, and real application background suspends the session. Guest data uses a separate `redesign-v2-disposable` namespace; no deployed save is silently converted.

`RedesignUpgradeBrowser` projects the complete catalogue into a reused result buffer. Its category/product/skill/search scope is also consumed by immutable Buy All quotes. It refreshes membership on structural command/filter changes, not cash ticks. The new saved native prefab is `Assets/Game/RedesignUI/Redesign Canvas.prefab`, authored by `BuildRedesignUI`, with eight reusable catalogue rows, upgrade details, an inline goal panel, frozen Buy All review, and a session router. Text material slots and the search caret are also serialized; focused TMP adapters bind these before initialization. Runtime code rebinds existing objects; no UI factory or growing pool is involved. The same prefab is available in `Redesign UI Preview.unity` and integrated in Main. `RedesignApplication` owns startup/recovery and `GameController` delegates without constructing the compatibility engine. Isolated Bootstrap bypasses legacy/cloud session initialization. [Native status and verification limits](Implementation/NativeUI.md).

The user deferred real IAP linking. `DevelopmentShop` commands are compiled only for Editor/development/lab use, persist one simulated operation, and require an explicitly marked disposable profile. Marked profiles cannot join live premium authority; ordinary releases reject them. The saved `RedesignShopScreen` keeps a No real payment banner visible, binds four content-defined packs/example prices, and simulates ready/loading/unavailable and pending/success/cancel/failure. Only the actual driver's isolated guest may enable it. Persistence precedes delivery, and restart resumes the same pending operation. Existing server/Unity Purchasing code is disconnected. [Development shop contract](Implementation/DevelopmentShop.md).

The saved native router also owns product/tap training, Talent collection/card details, persisted-result reveals and Prestige review. Prestige binds one run/command quote; passive income does not replace it, while a command change requires review. Reveals read an already committed result and only acknowledge its operation ID; animation cannot draw or charge. A pending reveal resumes when a session is rebound. These views are verified in the isolated preview and two actual Bootstrap-to-Main sessions, including persisted reveal restoration after restart.

Skill details use `PreviewSkill` for the actual owned effect or clearly labeled base-unlock projection, including Talent-adjusted timings and Bulk Order payout. The same core payout helper serves preview and activation. The return screen reads a previously committed offline receipt; its actions acknowledge the receipt ID and navigate without granting again. Main automatically presents settled return receipts before gameplay input. Home completes all 13 native states, using eight fixed shelves, a rate-limited counter and six saved feedback slots. Utility dialogs block the gameplay surface without suspending production.

The Main utility adapter reuses saved copies of Settings/Privacy/Store Name/Save Recovery. Durable preference commands preserve economic quotes; names are displayed without rich-text interpretation. Recovery retries the same profile, including any initial offline settlement, and never silently starts over. User-facing account/privacy text identifies the isolated guest; live Google services stay disconnected. Saved audio sources use original synthesized motifs and respect sound/music preferences. [Main evidence and device limitations](Implementation/NativeUI.md).

## Legacy compatibility runtime

The following contracts describe the preserved older controller/economy used by compatibility fixtures. It does not run in redesigned Main. They are not the new Fame/Talent design. Ad behavior has already been retired from this compatibility path.

`Catalog` is authored as a ScriptableObject snapshot in `GameContent`. Products, ordinary upgrades, skill durations/cooldowns/values and Legacy ranks/costs/values are data; economic behavior is implemented by deterministic runtime rules. Product and upgrade IDs are stable strings. Changing the built-in `Catalog.Create()` defaults does not silently overwrite existing definitions. Regenerate or edit the asset intentionally, export with Prepare Project, then rerun the simulator with `--catalog Documentation/ContentCatalog.json`.

`Amount` stores a nonnegative normalized base-10 mantissa and exponent. Earnings can exceed IEEE double magnitude; precision is approximately 15 significant digits, appropriate for an incremental economy. Ranks, counts, receipt IDs and reputation do not use this approximate type.

`GameEngine` owns commands: Tap, ProductQuote/BuyProduct, BuyTap, BuyUpgrade/BuyAll, ActivateSkill, PreviewPrestige/Prestige, BuyLegacy, ResolveOffline and RewardAd. UI displays these values and does not implement separate price/income formulas. Cosmetic traffic never drives simulation.

Product prices are a geometric series with growth 1.12. Income combines level, milestone, run-product, run-global, Legacy-product, Legacy-global and temporary multipliers. Bulk Order uses NormalIncome. Sponsor extras and offline advertising rewards are recorded separately from prestige-eligible earnings.

Prestige uses `floor(5 * sqrt(eligible / threshold))`, gated by owning eight families and reaching the threshold, capped at one million reputation per reset. A quote binds run ID, revision and reward. Confirmation pauses economic progression so the displayed quote remains exact. Modal time is intentionally excluded from income; absolute cooldown timestamps continue after the dialog closes.

Offline income is 50% of normal product income, capped at 8 + 2 × offline Legacy rank hours. The anchor is the greater of saved time and the current simulation clock; backward device clock changes grant zero income. Reconciliation persists the new anchor and reward together. Local clock advancement can still accelerate a fully offline game; there is no server clock or anti-cheat promise.

`DisabledRewardedAds` is the compatibility adapter. Sponsor/offline advertising actions cannot grant rewards, and AdMob/UMP dependencies and scene offers have been removed. Historical receipts remain readable for save compatibility. No ad service initializes from the new or preserved UI.

The preserved screen prefabs use UGUI, TextMeshPro, a 1080×2200 reference resolution and Screen.safeArea. Main stores their presenter references on GameController; GameView binds the shared Home canvas and routes navigation and dialogs without constructing UI at runtime. Required screen references are checked at startup. The obsolete UI copies and their builder methods have been removed from the prefabs and HTML Importer scene.

The shared Home shop stays visible above the lower Player, Products and Legacy panels, which retain their ScrollRects. ShopTapTarget accepts only short pointer gestures starting on the shop. Lower controls live outside that event hierarchy. The saved screen artwork and product displays are referenced directly by their presenters.

Audio is synthesized locally from original short bell motifs, with independent sound/music settings. Home owns the saved cash popups and celebration image. Reduced motion disables popup movement and celebrations.


Bootstrap.unity is the first build scene. Its saved 1080×2200 uGUI canvas initializes identity and selects a prepared PlayerSessionHost session before Main. Main entered directly redirects through Bootstrap; isolated smoke tests use temporary guest sessions and disabled ads. All startup states reuse serialized objects. Guests never initialize Firebase auth/cloud services. Google accounts require ownership and a server-confirmed save, use server time for offline reconciliation, and pause when connectivity or ownership is lost; see CloudSaves.md. Settings exposes the serialized account entry.
